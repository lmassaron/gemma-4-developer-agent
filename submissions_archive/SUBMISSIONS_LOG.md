### Why v13 Regressed (0.13 vs 0.15 on v10) & How v14 Fixes It:
1. **Loss of Best-Guess Edit Mandate**: `v10` scored 0.15 because Rules 7 & 8 forced a defensive edit onto disk by Turn 5/8. Many SWE-bench issues are simple null/type guards where an educated guess passes the test suite. `v13` removed this mandate, telling the model only "do not submit if patch is empty", which led to analysis paralysis and timeouts on tasks `v10` solved.
2. **Nested Tool Encapsulation (FM6)**: `v13`'s multi-tool schema confused Gemma 4, causing it to emit `edit_file` inside `run_command` (`bash: edit_file: command not found`), failing edits silently.
3. **`v14` Synthesis**: Combines `v10`'s aggressive Turn 5 edit mandate and Call 8 emergency best-guess with `v14`'s quoted heredoc runner (`python3 - <<'PY' ... PY`), clean tool separation, and mandatory `git diff --stat` verification.

1. **The Two-Gear Triage Strategy**: High-precision 6-turn resolution on 1-file bugs (Rich, Requests, Utils) + fast triage on complex cross-file bugs (FastAPI) to protect the 12-hour Kaggle ceiling.
2. **Quoted Python Heredocs (`python3 - <<'PY' ... PY`)**: Completely eliminates Python string quote collisions and syntax errors inside inline replacement scripts.
3. **Mandatory `git diff --stat` Self-Verification**: Catches silent replacement failures where indentation or whitespace caused `replace()` to modify 0 lines before calling `submit_patch`.
4. **Hard 0-Byte Barrier**: Rejects empty patch submissions, permanently solving the premature surrender failure mode (FM5).

1. **Peak Efficiency with v10**: `v10_lean_thinking` achieved the fastest average task time across the entire series (**269.2s per task**), reducing `requests_7205` to a record **81.97s in just 6 turns** (3.3x faster than v7_pro).
2. **FastAPI Loop Elimination**: On `fastapi_11194`, `v10` avoided both the 25-turn grep loop of v8 and the generation timeout of v9, concluding with a clean `submit_patch` in 278.6s (safely inside the 5.5m budget).
3. **Thinking Budget Tuning**: Lowering `thinking_budget` from 4096 to 1536 tokens shaved ~15-20s of inference latency per turn, allowing 2x more productive turns per minute.
1. **Speed & Efficiency**: `v9_loop_breaker` achieved the fastest resolution time on `requests_7205` (**84.4s in 7 turns**), a **3.2x speedup** over `v7_pro` (268.0s) and a **28% speedup** over `v8_call_paced` (118.7s).
2. **Reproduction & Verification Discipline**: On `requests_7205`, `v9` dynamically verified and applied a 791-byte patch with clean syntax validation and submitted immediately without wasting turns.
3. **Loop Breaking**: The anti-repetition circuit breaker eliminated the 25-turn grep loops on `fastapi_11194`, preventing useless repetitive calls.
4. **Budget Safety**: Strictly adheres to the 5.5-minute per-task ceiling (`eval_config.yaml`), guaranteeing that a 120-task Kaggle evaluation run finishes inside 11.0 hours with an ample safety buffer.
